# 已知限制

本工具的证据来自对 SQLite 文件结构的独立解析，而不是 SQLite 官方 `integrity_check`。了解以下限制，才能正确解释 `ok`、`partial` 和各类异常。

## 1. 输入范围

- 只接受一个本地主数据库文件，不接收目录、网络路径、多个数据库或 SQLite URI 作为审计目标。
- 只支持普通页式 SQLite 3 主文件。不处理加密数据库、加密页、自定义 VFS、页压缩、非标准页大小或非标准文件头扩展。
- 不读取、合并或修复 rollback journal、WAL、SHM。存在 `-wal` 时只提示结果不包含未合并帧。
- 输入文件必须至少有 100 字节；空文件、目录、符号链接指向的非普通文件会被拒绝。
- 输入文件按路径打开并一次性读入内存；工具不复制快照到临时目录，也不对文件加共享锁。

## 2. 一致性与并发

- 审计在读取时不对数据库加锁，也不阻止其他进程写入。
- 如果审计期间有活跃写者或 checkpoint，内存中的字节可能来自不同时刻；报告可能混合页状态。
- 工具以页大小切分并检查文件长度与页数声明，但不能证明读取期间文件没有被改写。
- 推荐流程：在授权范围内制作稳定副本，确认没有活跃连接后再审计。工具不提供复制、备份或停写能力。

## 3. 不是完整性检查替代品

- 不执行 SQLite `PRAGMA integrity_check` / `quick_check`。
- 不验证 B 树键顺序、rowid 排序、索引项唯一性、索引与表的一致性、外键、CHECK 约束或触发器语义。
- 不验证 cell 中记录的 SQL 文本是否可编译、schema 对象内容是否互相一致。
- 不检查普通表记录内部 serial type 的语义、字段值范围、文本合法性或业务约束。
- 不检查 freelist 页中的旧内容，也不检查 secure-delete 是否生效。
- 不验证所有页校验和（SQLite 普通页面格式没有逐页校验和）。
- 因此，结论 `ok` 只表示**在已实现的结构规则集合中未发现问题**，不代表数据库逻辑上完全正确或可用于恢复。

## 4. 损坏时的部分结果

- 页大小不可用、usable size 不可用、文件不足一个头或实际页数不足以按页切片时，停止页级遍历，返回 `status=partial`，并产生 `AUDIT_PARTIAL_RESULT`。magic 非法但页大小仍可安全切片时会继续解析页，同时把结果标为 `partial`。
- B 树 cell 解析失败时跳过该 cell，继续审计同页其它可解析 cell；失败位置以 `PAGE_CELL_PARSE_FAILED` 记录。
- 遇到子页越界、环或重复引用时，不沿着被拒绝的边继续遍历；因此后续页可能被标记为孤儿。
- freelist 遇到越界、环或结构错误时停止该链，保留已发现前缀；声明的 freelist 总数可能无法对账，整体状态标为 `partial`。
- 溢出链遇到断链、环、重复或安全上限时停止，保留已解析前缀；报告标记 `incomplete`，整体状态标为 `partial`，不会猜测缺失页的内容。
- 孤儿页只表示当前可达图没有解释它，不等于它一定是损坏页；可能来自部分遍历、未知页类型或合法但未登记的结构。
- `partial` 结果的异常计数不是完整损坏数量，不能当作数据库修复清单。

## 5. 安全上限与截断

- `max_pages`（默认 100000）限制 B 树遍历页数；达到上限时报告只覆盖前缀，并产生 `BTREE_TRAVERSAL_LIMIT`。
- `max_btree_depth`（默认 64）用于异常告警，不强制截断，但极深 B 树可能意味着损坏或恶意构造。
- `max_overflow_chain`（默认 4096）限制单条溢出链；达到上限时产生 `OVFL_LIMIT_REACHED`。
- `max_findings_per_code`（默认 250）限制每个错误码保留的异常条数。被截断的同类异常仍在内部扫描中计数，但报告只列前 250 条；不要把报告条数当作总命中数。
- `top_pages`（默认 10）限制 top 碎片页和 top 低利用率页列表长度，不改变全页汇总。
- 这些上限是防止异常文件造成失控遍历的安全阀，不是 SQLite 格式限制。

## 6. 内存与规模

- 输入文件被完整读入内存；大文件需要相应的可用内存。
- 页解析、B 树队列、溢出链和报告页账都会占用内存。默认上限针对常规审计，超大数据库应调整配置并在隔离环境运行。
- 报告包含每个解释页的明细；页很多时 JSON 和 HTML 会相应变大。
- 不提供流式处理、分片审计或增量续跑。

## 7. 确定性的边界

- 页记录按页号排序，findings 按级别/页号/错误码等稳定键排序，JSON 使用排序键和固定缩进。
- 报告包含输入文件的绝对路径、mtime 和内存快照 SHA-256；同一内容放在不同路径或不同 mtime 下，报告不会逐字节相同。
- 报告核心的页结构、异常和汇总对同一份字节快照是确定性的；`verify` 会重新计算并比对。
- 审计台账包含运行时间戳和自增 `run_id`，本身不是确定性报告内容。
- 浮点利用率保留 6 位小数；比较阈值时应使用报告中的数值，不要把展示文本当作精确有理数。

## 8. 解释与处置

- 工具不判断业务重要性，也不提供修复建议的自动化执行。规则中的处置建议只是人工复核提示。
- `SPACE_UTILIZATION_LOW` 和 `SPACE_FRAGMENTATION_HIGH` 是策略告警，不是损坏结论；稀疏页、短行表和删除模式都可能触发。
- `HDR_PAGE_COUNT_MISMATCH` 可能是合法尾部预留、文件复制中断或写入竞态，需要结合上下文判断。
- `SCHEMA_SIDECAR_UNAVAILABLE` 是旁证不可用，不一定是数据库损坏；例如 sqlite3 无法打开严重损坏文件时仍可能得到部分页级证据。
- `HDR_WAL_PRESENT` 是信息提示，不是错误；它表示本次结果的范围有限。

## 9. 输出与安全

- 报告内含文件路径、文件哈希、schema 对象名称和页结构证据；请按组织的数据分类要求保存。
- HTML 是自包含静态文件，不含外部资源或脚本，但仍是本地文件，不应视为经过身份认证的审计凭证。
- `integrity.digest` 只能检测报告内容是否与摘要一致；它不防伪造，不是数字签名。
- 审计台账是独立的 SQLite 文件，可能包含相同的路径摘要、异常文本和结构证据；应按同等敏感度保护。
- 工具拒绝把报告或台账写到被审计数据库的同一路径，但不能阻止用户把输出目录设置为其它敏感位置；输出位置由操作者负责。

## 10. 不提供的功能

不修复、不 VACUUM、不 REINDEX、不恢复删除记录、不做取证雕刻、不导出记录值、不合并 WAL、不处理加密数据库、不连接远程数据库、不上传文件、不提供常驻服务、不做查询性能分析或索引建议。详见 [COMPLIANCE.md](COMPLIANCE.md)。
