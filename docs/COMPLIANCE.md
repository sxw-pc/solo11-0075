# 合规与安全边界

`page-ledger` 是一个本地只读审计工具。它的设计目标是让授权人员在不修改数据库快照的前提下，复核页结构和空间账本。以下约束是产品边界，不是可选项。

## 1. 授权范围

- 只审计**本人拥有**或**已获得明确书面/组织授权**的本地 SQLite 文件。
- 不得用于未经授权的系统、他方数据库、规避访问控制或取证恢复。
- 审计前应确认文件来源、保管责任和留存期限；报告可能包含文件路径、schema 对象名称和文件哈希，应按组织的数据分类要求保存。
- 本项目不提供、也不应被改造成远程扫描、批量收集或上传服务。

## 2. 只读保证

工具对被审计数据库文件采用以下方式：

1. 以二进制只读模式 `open(path, "rb")` 读入快照；不调用写入 API。
2. 用 `mode=ro&immutable=1` 的 SQLite URI 做 schema 旁证；连接设置 `PRAGMA query_only = ON`，只执行 `PRAGMA page_count` 和只读的 `sqlite_schema` 查询。
3. 不执行 `VACUUM`、`REINDEX`、`PRAGMA writable_schema`、`PRAGMA journal_mode`、DDL、DML 或任何用户提供的 SQL。
4. 不重命名、移动、删除、截断或改写原文件；不创建同名 `-wal`、`-shm`、`-journal` 文件。
5. 审计台账写入独立的 SQLite 文件（默认 `<out>/audit-ledger.sqlite`）。CLI 会拒绝让报告或台账路径与被审计文件相同，避免覆盖输入。
6. 输出目录由用户指定；报告固定写入其中的 `report.json`、`report.md`、`report.html`，台账默认写入 `<out>/audit-ledger.sqlite`，也可由 `--ledger` 指向别处。若将输出目录设置为输入文件所在目录，请自行确认不会与既有业务文件重名。工具会拒绝让报告或台账路径与被审计文件相同。

只读保证针对工具的代码行为。操作系统权限、文件系统快照、外部进程和存储介质仍需由操作者控制。

## 3. WAL 处理

若输入文件旁存在同名 `-wal`：

- 只在页快照中记录 `wal_present=true` 和 `wal_name`；
- 产生 `HDR_WAL_PRESENT` 信息和限制说明；
- **不读取、不合并、不修改** WAL；
- 报告只反映主文件中已落盘的页，不包含 WAL 未合并帧。

需要包含最新已提交事务时，应在获得授权的数据库副本上，用 SQLite 自身的受控流程完成 checkpoint/复制，然后对稳定副本运行本工具。本项目不执行也不自动化该流程。

## 4. 完全离线

- 运行期只 import Python 标准库；没有 HTTP、套接字、云 SDK、包管理器调用或遥测。
- HTML 报告使用内联 CSS，不引用 CDN、外部字体、远程图片、脚本或 iframe。
- 测试和 fixture 生成本地运行，不下载真实数据库或远端样本。
- 运行 `audit` / `verify` 不需要网络连接。
- 项目不包含密钥、令牌、公司名、真实域名、用户数据或真实数据库文件。

测试使用 pytest；它是开发期测试依赖，不是运行期依赖。项目不会在审计命令中自动安装 pytest 或任何包。

## 5. 数据最小化

- 不解析、展示或统计普通表的字段值。
- 不进行敏感数据发现、内容搜索、导出或画像。
- 只对 `sqlite_schema` 的元数据做结构解析；schema 名称也仅用于对象对账。
- 报告不包含行内容、索引键值、freelist 旧内容或溢出 payload 内容。
- 报告记录文件路径和哈希是为了可复核性与完整性校验；如果需要最小化路径信息，应在受控的本地流程中处理报告。

## 6. 明确禁止的功能

本项目不实现，也不应扩展为：

- 修复损坏页、重建索引、VACUUM、页级写回；
- 恢复删除记录、取证恢复、数据雕刻；
- 导出业务数据、解析记录值、执行用户 SQL；
- 合并 WAL、读取未提交事务；
- 处理加密 SQLite、自定义 VFS、压缩页或非标准页格式；
- 连接远程数据库、上传文件、发送邮件/消息、调用外部 API；
- 常驻 Web 服务、在线并发写库审计、性能基准或索引建议；
- 规避授权、隐藏访问、批量收集或攻击性利用。

## 7. Fixture 与示例

`fixtures/build_fixtures.py` 只使用 Python 标准库生成合成数据库。表名、列名、行标识和文本均为合成内容，例如 `products`、`orders`、`note-...`。生成器不读取仓库外的数据库，也不访问网络。

`fixtures/generated/` 中的 `.db` 文件是本地生成物，不应作为源文件提交；`.gitignore` 默认忽略它们。测试会在会话开始时重建 fixture，因此仓库不需要携带二进制样本。

## 8. 报告与审计台账

- `report.json` 包含完整结构结果和完整性摘要；`report.md` / `report.html` 是便于人工阅读的派生视图。
- `audit-ledger.sqlite` 记录运行元数据、异常、页汇总和规则汇总，默认与报告同目录；它是**新的审计产物**，与被审计数据库相互独立。
- `verify` 只读取报告和原始数据库，不写报告、不写数据库、不创建审计台账。
- 报告完整性摘要用于检测报告内容被改动，不是数字签名，不提供身份认证或不可抵赖性。

## 9. 操作者责任

- 在授权范围内选择输入文件，并优先使用稳定副本。
- 不要在数据库仍有活跃写入时期待一致性快照；本工具不获取文件锁，也不冻结写入。
- 按组织要求保护报告、路径、哈希和审计台账。
- 若需要修复或恢复，应停止使用本工具并交由具备授权的专业流程处理；本工具只负责描述证据。
